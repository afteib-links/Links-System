# PDF日報のローカルOCR

PDFと派生画像は既存の取込保存領域に置きます。通常の取込閲覧権限と原本の3年の保存期限を派生画像にも適用します。期限後はAPIから取得できません。バックアップ・物理削除は既存の保存領域の運用に従います。

## 構成・更新

リポジトリのDocker更新ツールで `app`、`db`、`ocr` を更新します。初回ビルドのみ依存パッケージと公式モデルをダウンロードします。Python依存は `requirements.lock`、モデルは `fetch_models.py` のSHA-256で固定しています。実行時のOCRコンテナは外部接続できない `ocr_internal` ネットワークだけに接続し、原本を外部へ送信しません。

- PP-OCRv5 mobile / PaddleOCR 3.2.0 / PaddlePaddle 3.1.1、CPU 1スレッド、同時実行1。
- MariaDBの排他ロック、永続ジョブ、進捗・試行回数・エラーを利用します。再起動時に実行中ジョブを復旧し、3回失敗後は画面から明示再試行します。保存済みの原読取行は再試行で上書きしません。
- 初期メモリ上限1GB。`OCR_MEMORY_LIMIT` で変更できます。NAS全体のメモリ使用量も確認してください。
- 依存やモデルを戻す場合は旧イメージへ戻します。新規migration 047と保存領域は削除しません。モデル更新は別版として再検証します。

## 操作

「データ取り込み」でPDFを選び、案件と様式を指定します。各ページの回転、表の上下、行数、列の左右を指定して保存します。傾き補正後の画像に同じ領域設定を使います。比較画面では原本の該当行画像・原読取値・修正候補・現在値を確認し、行と項目を選んで反映します。既存行の更新には理由が必要です。右側の手修正はOCR側の再修正より優先されます。

OCRの停止・失敗時は「原本を見て手入力」で続行できます。原本PDFを開き、勤務日・時刻を入力して反映項目を選択します。OCRの解析中も他の日報入力は続けられます。

## 検証記録（2026-09-26）

匿名の活字3行PDFで、画像生成、PP-OCRv5解析、既存値保護、項目選択、二重実行、版競合、確認済みロック、原読取・初回入力元の保持をAPIで検証しました。CPU 1・メモリ上限1GBの外部通信不可コンテナで、解析9.52秒、プロセス最大RSS 523,284KBでした。この測定は開発PC上のDockerです。

実際の手書き帳票の項目別正解率、修正回数、手入力との所要時間比較、およびQNAP / メモリ2GBのASUSTOR実機測定は未実施です。実帳票をリポジトリへ入れず、匿名化した対象様式で運用開始前に測定します。低信頼度・不明文字は自動反映しません。
