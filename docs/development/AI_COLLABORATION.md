# 複数AI開発運用

## 目的

Cursor、Antigravity、Codex、Cloud Agent、将来のローカルLLMを切り替えても、仕様・作業状況・変更理由を失わず、安全にLinks-Systemを開発する。共有地点はGitHubとリポジトリであり、特定PCや特定のAIチャットではない。

## 正本の置き場所

| 内容 | 正本 | 補助資料 |
|---|---|---|
| 業務仕様・設計判断 | `仕様MD/`、`05_decision_log.md` | 旧Excel、旧システム、会話ログ |
| 現在地 | `仕様MD/00_現状スナップショット.md` | GitHubのmain・PR一覧 |
| 作業中の担当・引継ぎ | GitHub Issue と Draft PR | チャット本文 |
| 実装内容 | PRの差分・コミット | ローカル作業ツリー |
| AI固有の起動方法 | `.cursor/`、`ANTIGRAVITY.md`、`AGENTS.md` | AIの個人設定 |

チャットは依頼と相談の場であり、決定後の内容は必ず仕様MDまたはIssue/PRへ転記する。これにより、別のAIや別端末からも同じ情報を参照できる。

## 役割

- **ユーザー**: 業務の事実、優先順位、曖昧な仕様の最終決定を行う。
- **実装AI**: 合意済みの1作業を、指定範囲で実装・検証・PR化する。
- **レビューAI**: 実装AIと異なるAIまたは異なるチャットで、仕様・金額・DB・権限・回帰を確認する。
- **調査AI**: コードや旧資産を読み、再利用可否・影響範囲・未確定事項を記録する。業務仕様を推測で確定しない。

1つのAIが複数の役割を行ってもよいが、金額・DB・認証・NASに関わる変更は、可能なら別AIのレビューを受ける。

## 作業フロー

```text
仕様確認 → Issue/作業ID → 専用ブランチ → Draft PR
     → 実装・検証 → レビュー → mainへマージ → スナップショット更新
```

1. 作業を開始するAIは、`AGENTS.md`、現状スナップショット、対象仕様を読む。
2. GitHub Issueに目的、対象仕様、担当AI、編集範囲、完了条件を記録する。小さな文書修正でIssueを省く場合も、PR本文に同じ項目を書く。
3. `origin/main`から専用ブランチを作る。命名は `cursor/<英語短名>-148a` を継続する。
4. 早い段階でDraft PRを作り、途中経過・未完了・触らない範囲を残す。
5. 実装者はPRの検証欄を埋め、レビュー者は仕様の正本と差分を照合する。
6. `main`へマージした大きな変更では、現状スナップショットと必要な決定ログを同じPRで更新する。

## 同時作業の境界

同時開発は、次の3条件をすべて満たす場合だけ行う。

1. Issueとブランチが別である。
2. 主な編集ファイルまたは責務が重ならない。
3. 両方のDraft PRに、相手が編集しない範囲を記載している。

同じmigration、同じ計算サービス、同じAPIルート、同じ画面、同じ仕様MDを同時編集してはいけない。重なった場合は、先に着手したDraft PRを基準に担当を分割する。

共有の作業ロックMarkdownは作らない。複数AIが同時更新してかえって競合するため、GitHubのIssueとDraft PRを作業中状態の正本にする。

## 変更の区分

### 単独実装しやすい変更

- 既存仕様に沿った画面文言、CSS、独立したプロトタイプ
- 読み取り専用の調査、仕様の索引、テスト追加
- 既存APIを変えないUI改善

### PRで影響確認が必要な変更

- API、画面、DBをまたぐ機能追加
- `db/migrations/` の追加
- 日報の計算、請求・支払の集計、帳票テンプレート
- 依存ライブラリ、Docker、NASスクリプト

### 実装前に業務確認が必要な変更

- 金額計算順序、控除、税・端数、締日、振込日、FB出力
- 確定済み請求・支払の訂正、無効化、再発行
- 認証・権限、実データ移行・削除、外部送信

最後の区分では、仕様MDに決定を記録してから実装する。緊急修正でも、理由と復旧方法をPRに残す。

## 完了・引継ぎの最低情報

Draft PR本文に以下を残せば、別AIはチャット履歴に依存せず続きから作業できる。

```text
目的:
対象仕様:
担当AI / 作業ID:
変更したファイル:
変更してはいけない範囲:
未完了・確認待ち:
実施した検証:
次にすること:
```

ユーザーがAIへ依頼する際の短い依頼文は [`AI_WORK_REQUEST_TEMPLATE.md`](AI_WORK_REQUEST_TEMPLATE.md) を使う。
