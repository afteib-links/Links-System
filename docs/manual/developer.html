開発者マニュアル

機能の役割、設定の入れ方、匿名の記入例を3件以上ずつ載せた開発者向け資料です。画面の見た目は 画面俯瞰マニュアル を併用してください。

記入例はすべて架空です（【検証】 接頭辞のイメージ）。実在の顧客名・口座は使わないでください。

対象版: 現行SPA + Express + MariaDB / 作成日: 2026-09-05

1. この資料の対象

リポジトリを触る開発者・実装AI向けです。入口はリポジトリ直下の AGENTS.md です。作業開始時は 仕様MD/00_現状スナップショット.md と 仕様MD/00_AI共通_開発ガイド.md を先に読みます。

読み手この資料でやることやらないこと
機能追加する人画面の必須項目、APIの置き場、記入例NAS実機の障害対応の全手順
設定を初期投入する人マスタとシステム設定の入れ方本番の実データ移行判断
実装AIブランチ・migration・テストの約束仕様が矛盾している論点の独断確定

2. 構成とディレクトリ

ブラウザは vanilla JS の単一SPAです。React Router はありません。機能切替は frontend/js/app.js の openFeature(featureKey) です。データは MariaDB、APIは Express です。

ブラウザ → http://<host>:8080（Docker）または :3000（Cloud直接起動） frontend/ （静的SPA） backend/src/server.js （REST + セッション + PDF） MariaDB （db/migrations を起動時適用）
パス役割
frontend/js/画面。機能キーごとに1ファイルが目安
backend/src/routes/HTTP API
backend/src/permissions.js権限キーと機能の対応（実装の正）
db/migrations/連番SQL。既適用ファイルは書き換えない
仕様MD/業務仕様の正本
docs/manual/利用者／開発者向けHTMLマニュアル

3. 起動と環境変数

入力方法

.env.example をコピーしてリポジトリ直下に .env を作ります。.env はコミットしません。Docker ではホスト 8080 がコンテナ 3000 です。

cp .env.example .env docker compose up --build -d curl http://127.0.0.1:8080/api/health

Cloud Agent では Docker を使わず、ホストの MariaDB + cd backend && node src/server.js（ポート 3000）です。DB_HOST=127.0.0.1 にします。

4. Git・Issue・PR

1作業 = 1 Issue（または合意した作業ID）= 1ブランチ = 1 Draft PR。main へ直接pushしません。

入力方法

git checkout main && git pull origin main git checkout -b cursor/<英語短名>-148a # 実装後 git push -u origin cursor/<英語短名>-148a # → Draft PR to main

Cloud Agent のブランチ接尾辞は環境指定（例 -bf29）に従います。歴史的接頭辞 cursor/ はCursor専用ではありません。

9. 案件と金額データ

基本案件はひな形、個別案件は実行契約、金額データ（PriceSet）は適用期間付き単価です。日報は個別案件にぶら下がります。支払区分「分割」の個別案件だけが先払マトリクスに出ます（稼働0日でも表示）。

入力方法

  1. 基本案件で企業・テンプレ名・勤務時間・締日を保存する
  2. 金額データで基本案件または個別案件に期間付きPriceSetを付ける
  3. 個別案件で企業・パートナーを選び、必要なら「テンプレ反映」でディープコピーする
  4. 車両は所有元（企業／パートナー）を先に選び、その所属の車両だけを選ぶ

10. 日報

月次一覧から案件の日別グリッドへ入ります。保存のたびにサーバ側で再計算します。Excel/CSV取込のファイル内金額は使いません。取込操作は管理者・総務のみです。

入力方法

対象月を選ぶ → 案件の入力を開く → 開始・終了・休憩・距離・経費を入れて保存 → 日次確認 → 月次承認依頼 → 承認または差戻し。時間は H:MM（例 8:30）。警告があっても確認ダイアログで続行できます。

11. 精算・入出金

状態はおおむね 下書き → 営業確認済み → 最終確定（PDF＋入出金予定）→ 取消／訂正。請求は同じ請求先・取纏番号の案件だけ同時作成できます。支払の控除は最終確定時に載ります。

入力方法

  • 先払: 分割案件のセル金額を理由付きで変更 → 選択して予定作成。CSVはサイクル単位。
  • 請求/支払: 対象月一覧から下書き → 明細は理由必須 → 営業確認 → 管理回を選んで最終確定。
  • 入出金: 手動予定は管理回・入金/出金・相手先・件名・金額。実績は 1=実行 2=保留 3=取消。

記入例（3件以上）

13. マイグレーション

起動時に backend/src/migrate.js が schema_migrations を見て未適用SQLを流します。ファイルは db/migrations/001_… からの連番です。既に適用したSQLは書き換えず、次番号の新規ファイルを足します（016 は用途違いで2ファイルあるので、追加時は既存番号を確認）。

14. テスト・検証データ

匿名検証データは backend/scripts/seed_verification_data.js です。アプリ起動（マイグレーション完了）後、コンテナまたは PDF_DIR が書ける環境で実行します。本番 NODE_ENV=production ではリセットできません。

# Docker docker compose exec -T app npm run seed:verification docker compose exec -T app npm run verify:verification-data # 画面キャプチャ（マニュアル用） cd backend UI_BASE_URL=http://127.0.0.1:8080 npm run capture:manual
コマンド用途
npm test --prefix backend単体
npm run test:e2e-ui --prefix backend画面シェルのE2E
npm run test:e2e-advance --prefix backend先払マトリクスE2E
curl …/api/health起動確認。DBが down なら失敗
検証リセットは VERIFICATION_RESET_CONFIRM=DELETE_VERIFICATION_DATA が必要です。seed_key 付きの匿名行だけが対象でも、確認なしでは流しません。
