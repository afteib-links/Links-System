# 個別機能仕様書：2-2. 日報提出一覧画面

> **状態**: 2026-09-06 合意。画面イメージ先行のあと本実装。
> **参照**: [`09_日報・精算・帳票_業務要件.md`](09_日報・精算・帳票_業務要件.md)、[`計画/24_日報提出一覧.md`](計画/24_日報提出一覧.md)、画面イメージ [`画面イメージ/日報提出一覧_モック.png`](画面イメージ/日報提出一覧_モック.png)

## 1. 目的

パートナーが FAX・メール等で定期的に送る日報の **受領** を、事務側が案件×月3回で確認する。既存の日報入力・承認（`daily_reports`）とは別データであり、入力済み件数からの自動判定はしない。

## 2. 対象

- 削除されていない個別案件すべて（パートナー未割当てを含む）
- 締日が `5` / `10` / `15` / `20` / `25` / `end` のもの。不正な締日の案件は期間を計算できないため表示しない
- 未割当パートナーは `-` と表示する

## 3. 画面構成

先払マトリクスと同じ骨格。既存サイドバー・ヘッダー内に置く。メニューは「日々の運用」の **日報提出**（日報の隣）。UIビルダー対象外。

- 最上段: 対象月全体の総数カード（案件数 / 提出済み / 未提出 / 期限超過）。表フッターには置かない
- その下: 月選択、猶予日、今日
- 絞り込み: 案件・企業・パートナー検索、企業、パートナー、締日、状態（未提出 / 提出済み / 遅延）
- 表は先払と同じくサイクルを横並びにする。各サイクルは小見出し 3列（対象期間・予定提出日 / 提出状態 / 提出日）
- 行高は横並びに合わせて薄くし、文字は判読できる大きさにする
- 案件情報（左固定）の主表示は **パートナー名（作業員名）**。企業名は補助。列名は「プロジェクト情報」にしない
- 「不要」セルや灰色の無効オーバーレイは置かない。3サイクルは先払いと同じくすべて入力対象とする
- 案件別（右固定）: 提出 `n/3`、遅延件数、遅延合計日数
- 対象月全体のサイクル別内訳は表の見出し直下（最上段）に出す
- 狭い画面はマトリクス内だけ横スクロール。760px以下は案件別の右固定を解除する

各サイクルの横並び:

- 対象期間（`M/D〜M/D`）と提出予定日
- **提出トグル**（提出済み / 未提出）
- **提出日**。遅延日数（`+N日`）は提出日の下段に改行して置き、隣のサイクルと重ねない。手修正できる

## 4. 日付ルール

期間は先払いと同じ 5日系 / 10日系の3サイクル。

| サイクル | 5日系（締日5・15・25） | 10日系（締日10・20・末日） |
|---|---|---|
| 5日・10日締め | 前月26日～当月5日 | 当月1日～10日 |
| 15日・20日締め | 当月6日～15日 | 当月11日～20日 |
| 25日・末日締め | 当月16日～25日 | 当月21日～末日 |

- **基本提出日（提出予定日）** = 対象期間の最終日 + 1日（暦日。土日祝の繰りはしない）
- **期限日** = 基本提出日 + 猶予日
- 猶予日は全社共通のシステム設定 `daily_report_submission_grace_days`。初期値 1、範囲 0〜30
- **遅延日数（自動）** = 判定日 − 期限日（0以下は 0）
  - 提出済み: 判定日 = 提出日
  - 未提出: 判定日 = 今日（Asia/Tokyo）
- 遅延日数はセルの数値入力で 0〜365 の整数へ手修正できる。手修正値を保存する。提出トグルまたは提出日を変えたときは自動計算へ戻す
- 提出予定日は案件の締日で変わるため、列見出しではなく **セル内** に出す
- 「不要」表示は使わない

## 5. 操作

- トグル ON → 提出日が空なら操作日（JST）を自動入力し保存する
- トグル OFF → 提出日を空にして保存する
- 提出日は自動入力後も手修正できる。手修正してもトグルは ON のまま
- 未来の提出日は登録できない
- 遅延日数は数値入力で手修正できる。提出トグルまたは提出日を変えた保存では自動計算へ戻す
- 保存はセル単位。楽観ロック（`version`）不一致は再読み込みを案内する

## 6. 権限

機能キー `daily_report_submissions`。admin / system / soumu / sales / executive。パートナー・企業ロールには出さない。

## 7. データ

テーブル `daily_report_submissions`: 案件 × 対象月 × サイクル（`early` / `middle` / `late`）の提出フラグ、提出日、遅延日数（NULL は自動計算）、操作者、版。日報本体とは結合しない。
