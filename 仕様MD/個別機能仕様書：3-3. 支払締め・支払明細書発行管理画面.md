# 開発指示：3-3. 支払締め・支払明細書発行管理画面の実装

事前に共有している「運送業務基幹システム」の全体方針、マスタ定義、日報データ、および先払いデータに基づき、「支払締め・支払明細書発行管理画面」のフロントエンドプログラム（HTML/CSS/JavaScript）を作成してください。データの保存先はIndexedDB（またはLocalStorage）を用いたローカル保存を前提とします。

## 1. 画面の目的
日報画面で「承認済」となった支払データおよび「先払い実績」をもとに、パートナーごとの締日に合わせて支払額を集計・控除計算し、支払データを確定（締め処理・スナップショット保存）する。
案件ごとの明細保持、定額控除・先払い控除・その他費用の差し引き、および上段（支払明細）/下段（請求明細）の一体型帳票やマルチフォーマット（A・B・Cパターン・複合出力）に対応する。

## 2. 画面構成（SPAアーキテクチャ）

### 画面A：支払締め 対象一覧画面
* **対象月・締日セレクタ**:
  * 「対象年月（YYYY-MM）」と「締日」を選択し、支払対象データを抽出する。
* **支払対象リスト（プレビュー）**:
  * 承認済日報を持つパートナーの一覧を表示（仮承認・未確定データも仮集計額として確認可能）。
  * 表示項目: パートナー名、パートナー区分（個人/企業/個人事業主）、支払出力区分、案件総合計額、控除合計額、最終実振込額。
  * アクションボタン: 「詳細確認・締め実行（画面Bへ遷移）」。

### 画面B：支払詳細確認・控除調整・締め実行画面（帳票プレビュー）
* **支払・控除明細プレビュー**:
  * 案件ごとの売上/支払総額、および各自動控除項目の一覧を表示。
* **その他費用・調整行の追加UI**:
  * 「＋ 調整・その他費用を追加」ボタンを配置。
  * 資材代、独自の相殺金、追加手当、高速代立替など、任意の項目名と金額（プラス/マイナス）を入力して控除・加算できる仕組みを実装。
* **締め処理（スナップショット保存）アクション**:
  * 「支払を確定する（締め処理）」ボタンを押下。
  * 確定時、全計算結果・控除内訳・手動調整行を「支払履歴データ（payments / payment_details）」へ完全固定化（スナップショット保存）する。
  * 対象となった日報データの支払ステータスを「支払済（Paid）」へ更新する。
* **帳票出力（パターン選択・複合出力対応）**:
  * パートナーの「支払出力区分」に基づくデフォルト表示に加え、画面上で「Aパターン（支払＋請求）」、「Bパターン（給与明細）」、「A＋B両方出力」、および「将来のCパターン（カスタム）」を自由に選択して一括印刷/PDF出力できるUIを配置する。

## 3. 計算 ＆ 控除ロジック（支払心臓部）

### 自動控除および最終振込額の算出順序
1. **案件総合計額（月次支払合計）**: 承認済日報の支払金額の合計。
2. **自動控除項目の集計**:
   * ① **先払い（分割）実行額合計**: 「3-1. 先払い管理」で確定した該当月実績の合計。
   * ② **先払い時 振込手数料合計**: 先払い実行時に適用された振込手数料の合計。
   * ③ **定額控除**: 事務手数料 1,100円（税込）＋ 安全協力会費 8,800円（非課税）。
3. **その他費用・加減算（手動入力）**: 画面上で追加された任意の調整額（プラス/マイナス）。
4. **最終実振込額**:
   `最終実振込額 ＝ 案件総合計額 － (① ＋ ② ＋ ③) ＋ その他調整額`

## 4. 帳票レイアウト仕様（上下分割 ＆ 複数パターン対応）

### Aパターン：上下分割型 帳票レイアウト（印刷用CSS対応）
* **上段：支払明細エリア**
  * 案件総合計額（月次支払合計額）。
  * 差し引かれた控除額の総額と、その詳細内訳（先払い額、振込手数料、事務手数料1,100円、安全協力会費8,800円、その他調整項目）。
  * 差引後の**「最終実振込額」**を強調表示。
* **下段：請求明細エリア（パートナーからの請求根拠形式）**
  * 日報実績に基づく働いた条件・明細（例: 平日料金 5,000円 × 20日 ＝ 100,000円 など、料金区分ごとの数量・金額）。

### 帳票パターンの拡張性構造
* システム内部で帳票フォーマット（A: 支払＋請求、B: 給与明細、C: その他拡張）をテンプレートコンポーネント化し、単一出力・複数同時（両方）出力の切り替えを可能とする。

## 5. データ構造・トランザクション（支払スナップショット）

**① 支払ヘッダテーブル (payments)**
* `payment_id` (PK, 自動採番), `partner_id` (FK)
* `target_year_month` (対象年月: YYYY-MM), `closing_date` (締日)
* `total_gross_amount` (案件総合計額/月次支払合計)
* `advance_payment_deduction` (先払い控除合計)
* `transfer_fee_deduction` (先払い振込手数料控除合計)
* `fixed_deduction_admin` (事務手数料控除: 1,100)
* `fixed_deduction_safety` (安全協力会費控除: 8,800)
* `other_adjustment_amount` (その他手動調整額合計)
* `total_deduction_amount` (全控除額合計)
* `final_payout_amount` (最終実振込額)
* `payment_status` (状態: `issued` [確定済], `transferred` [振込済] 等)

**② 支払明細・控除内訳スナップショット (payment_details)**
* `payment_detail_id` (PK), `payment_id` (FK)
* `detail_type` (区分: `work_item` [稼働明細], `deduction_item` [控除内訳], `adjustment_item` [手動調整])
* `item_name` (品名・項目名称: 例「平日料金」「先払い控除」「〇〇立替金」等)
* `unit_price` (単価), `quantity` (数量), `amount` (金額)

## 6. プログラムソース作成の絶対条件
* すべての機能を省略せずに作成し、コピペでそのまま動作する完全なコードを出力してください。
* 控除額の自動合算・手動調整行の動的追加・最終実振込額のリアルタイム再計算ロジックを確実に実装すること。
* 1枚の用紙に上段（支払明細）と下段（請求明細）が美しく収まる印刷用スタイル（CSS）を組み込むこと。
* Aパターン、Bパターン、A＋B両方出力などの切り替えロジックを確実に実装すること。
* 仕様の不明点は勝手に補完せず、必ず質問してください。
