# 運送業務基幹システム：ログイン・ユーザー・機能権限仕様

## 1. 目的

約4名が同時利用する前提で、ユーザーごとに **ログイン可否** と **利用できる機能** を制限できるようにする。

## 2. 認証方式

* 簡易ログイン（ログインID + パスワード）
* パスワードはハッシュ保存（平文保存禁止）
* ログイン後はセッション（Cookie）でAPIを保護
* 無効化（`is_active = false`）されたユーザーはログイン不可

## 3. ロール

| ロール | 意味 | 機能権限の扱い |
|--------|------|----------------|
| `admin`（管理者） | システム管理・締め・承認など | **全機能を自動付与**（個別チェック不要） |
| `staff`（事務担当） | 日常の入力・参照 | 付与された機能のみ利用可 |

## 4. 機能権限（feature）

ユーザーごとに、次の機能キーの利用可否を設定する。

| 機能キー | 表示名 | 対応予定機能 |
|----------|--------|--------------|
| `companies` | 企業マスタ | 企業マスタ管理画面 |
| `partners` | パートナーマスタ | パートナーマスタ管理画面 |
| `projects` | 案件マスタ | 案件マスタ管理画面 |
| `daily_reports` | 日報 | 日報登録・一覧・承認 |
| `advances` | 先払い | 先払い（分割）管理 |
| `invoices` | 請求 | 請求締め・請求書発行 |
| `payments` | 支払 | 支払締め・支払明細書発行 |
| `users` | ユーザー管理 | ユーザー作成・権限変更 |

### 制御ルール

* **画面**: 権限のない機能はメニューに表示しない
* **API**: 権限のない操作は `403` で拒否する
* 事務担当は、利用機能を1つ以上持っている必要がある
* 自分自身の無効化、自分自身からの「ユーザー管理」権限削除、最後の管理者削除は禁止

## 5. ユーザー管理画面

* `users` 権限を持つユーザー（通常は管理者）のみ利用可能
* できること:
  * ユーザー新規作成
  * 表示名・ロール・パスワード変更
  * ログイン許可/禁止
  * 利用機能のチェック設定
  * ユーザー削除（論理削除）

## 6. 初期ユーザー

* 初回起動時、管理者が0件なら `.env` の初期管理者を1名作成する
* 初期管理者は全機能権限を持つ

## 7. 関連実装

* API: `/api/auth/*`, `/api/users/*`
* ミドルウェア: `requireAuth`, `requireRole`, `requirePermission`
* DB: `users.permissions`（JSON）, `users.is_active`
