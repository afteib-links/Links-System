# 1-4. 基本管理画面

## 1. 目的

企業、基本案件、個別案件、金額データを、登録上の親子関係を保ったまま1画面で確認し、既存の各編集画面へ移動できるようにする。登録・更新処理は既存の各マスター画面を正本とし、本画面では一覧と詳細プレビューだけを提供する。

## 2. 利用権限とメニュー

- 機能キーは `base_management`、メニュー名は「基本管理」とする。
- 管理者、システム担当者、総務が利用できる。
- 既存の企業マスタ、パートナーマスタ、基本案件、個別案件、金額データ管理メニューは残す。

## 3. 画面構成

- 企業 → 基本案件 → 個別案件 → 金額データ → 詳細プレビューの5列ミラーカラムとする。
- 列見出しは16px、項目名は18px、補助情報は14px、通常行は88pxを基準とする。
- 5列を収められない幅では各列を縮小せず、画面本体を横スクロール可能にする。
- 画面上部に「クリックで詳細／ダブルクリックで編集画面」の案内と、選択階層のパンくずを表示する。

## 4. 操作

- 各階層の行をクリックすると、その項目に応じた詳細プレビューを表示する。
- 各階層の行をダブルクリックすると、IDを保持して既存編集画面を直接開く。
  - 企業: `companies` + `company_id`
  - 基本案件: `base_projects` + `base_project_id`
  - 個別案件: `projects` + `project_id`
  - 金額データ: `price_sets` + `price_set_id`
- 詳細プレビューにも「編集を開く」「編集画面へ」を表示する。
- 項目選択では画面全体を再描画せず、選択表示、下位カラム、パンくず、詳細プレビューだけを更新してスクロール位置を維持する。
- 企業列と基本案件列に「全対象」を配置する。企業の全対象は全企業、基本案件の全対象は選択企業内を対象に、4階層を行結合した一覧で表示する。
- 全対象中も実データの各セルをクリックしてプレビュー、ダブルクリックして編集できる。
- 下位データがない場合は「基本案件なし」「個別案件なし」「金額データなし」を表示し、親階層を省略しない。
- 企業は企業名・締日、基本案件と個別案件は名称・締日、金額データは名称・適用開始日で昇順／降順を切り替える。

## 5. 詳細プレビュー

- 一覧表は置かず、選択した1項目の概要、関連件数、次に確認・設定する内容、最終更新日時を表示する。
- 企業: 企業No、名称、フリガナ、締日、支払日、基本契約日、基本案件数、個別案件数。
- 基本案件: No、企業、テンプレート名、担当、業種、勤務条件、締日、個別案件数、金額データ数。
- 個別案件: No、企業、基本案件、パートナー、担当、業種、運用開始日、締日、支払区分、金額データ数。不足設定は注意表示する。
- 金額データ: No、名称、企業、基本案件または個別案件、適用開始・終了日、料金行数、請求単価合計、支払単価合計、単価差額合計、参考利益率、適用状態。単価合計は登録料金行を合算した確認用参考値であり、月次の請求額・支払額ではないことを明記する。既存編集画面のコピー改定へ案内する。
- 共通ヘッダー、列見出し、詳細プレビュー見出しは縦スクロールさせず、各一覧と詳細プレビュー本文だけを独立して縦スクロールする。
- スマートフォン・タブレットでも、通常表示の各カラムと全対象表示を縦スワイプして最下部まで移動できるようにする。横方向のミラーカラム移動と、カラム内部の縦移動を分離する。

## 6. データとAPI

- `GET /api/base-management` で、論理削除されていない `companies`、`base_projects`、`projects`、`price_sets` と料金行数を取得する。
- 本画面専用の保存APIとDBテーブルは追加しない。
- 金額データの親子関係と適用期間は `05_project_price_relationship.md` を正とする。

## 7. 検証

- 通常の順次選択、全企業、選択企業内の全基本案件、各列のソートを確認する。
- 各階層のクリック、ダブルクリック、プレビュー内編集ボタンを確認する。
- 下位データなし、基本案件用金額データ、個別案件用金額データを確認する。
- 権限、JavaScript構文、API応答、主要デスクトップ幅と横スクロールを自動テストする。
