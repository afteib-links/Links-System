# 3. 業務フローと機能連携

## 標準フロー

```text
企業マスタ ─┐
             ├→ 基本案件 → 個別案件 → 金額データ
パートナー ─┘                         │
                                      ↓
日報提出確認 → 日報入力・計算 → 月次確認・承認
                                      ├→ 請求下書き → 確定・請求PDF → 入金予定
                                      ├→ 支払下書き → 確定・支払PDF → 出金予定
個別案件 → 先払3サイクル ──────────────→ 出金予定
                                      ↓
                            入出金管理・銀行CSV
                                      ↓
                              実績・差額・履歴

日報・請求・支払 ─────────────────────→ 収支分析
```

## 機能を分けている理由

|似て見える機能|分離理由|
|---|---|
|基本管理と各マスタ|基本管理は関係を横断確認する入口、各マスタは正本を編集する場所|
|基本案件と個別案件|ひな形の改定で既存契約を自動変更しないため|
|個別案件と金額データ|契約条件と期間別単価のライフサイクルが異なるため|
|日報と日報提出|勤務実績の入力と、FAX・紙・メールを受領した事実は別だから|
|請求と支払|同じ日報を使っても、売上と原価では相手先、税、控除、帳票が異なるため|
|先払・支払・入出金|月途中の前払、月次精算、銀行で動かす予定・実績は処理段階が異なるため|
|画面ヘルプ・利用マニュアル・設計書|その場の説明、操作教育、業務意図・内部設計で目的が異なるため|

## マスタ変更の伝播

- 企業・パートナーの最新表示情報は参照画面へ反映するが、確定帳票の宛先・金額は発行時スナップショットを保持する。
- 基本案件から個別案件を作るときは必要な契約条件をコピーし、その後は別ライフサイクルとして管理する。
- 金額データは有効期間と改定系列で解決し、日報日付に適用される版を選ぶ。
- 計算ルールは下書き、検証、公開を分け、公開済み版を直接書き換えない。

## 月次締めと確定

事務は現在保存されている日報から請求・支払の下書きを作成できます。営業確認または最終確定では、対象案件の日報承認と下書きの根拠一致を確認します。発行時に帳票番号、明細スナップショット、PDF、入出金予定を作成します。

発行後の変更は元帳票を上書きせず、理由を伴う無効化と訂正下書きを作ります。入出金が実行済みなら、元実績を変更せず差額予定を追加します。
