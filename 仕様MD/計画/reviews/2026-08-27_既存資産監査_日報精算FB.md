# 既存資産監査（Links-System）— 日報・精算・帳票・入出金・FB

作成日: 2026-08-27

作業ID: GitHub Issue #24

対象リビジョン: Links-System `origin/main` / `2a38214`

監査方法: コード、SQL migration、画面実装、HTMLプロトタイプを読み取り専用で確認

## 結論

日報入力、PriceSet、請求・支払のヘッダー／明細／日報関連は、**修正して再利用する土台**とする。

前払は既存実装の業務上の意味が新要件と異なるため、既存テーブルを正本にせず再設計する。分割返済、月6回の入出金管理、FB、正式PDF生成、Excel取込は、現行コードに本実装を確認できないため新設計が必要である。

BMSの監査と情報管理は別作業として担当分離されており、本記録の対象外とする。

## 現行実装として確認した事実

### 日報

- `daily_reports`と`/api/daily-reports`があり、案件、企業、パートナー、勤務日、開始・終了、休憩、距離、交通費等を保持する。
- 請求計算額、支払計算額、適用PriceSet、請求上書き額、支払上書き額を保持する。
- `draft`、`confirmed`、`approved`、`rejected`の状態と、請求済み・支払済みの関連状態を持つ。
- 承認済み日報の編集禁止と、versionを使った競合検出の仮組がある。

### PriceSetと計算

- `price_sets` / `price_set_lines`に適用期間、曜日、計算区分、請求単価、支払単価を保持する。
- 勤務日に有効なPriceSetを選択し、請求・支払の基本額と不足時間の簡易計算を行う。
- 現行計算は基本額中心の最小構成であり、超過、深夜、休日、距離、交通費、複数作業、案件別の特殊条件を網羅していない。

### 請求

- `invoices`、`invoice_details`、`invoice_daily_reports`がある。
- 承認済み・未請求の日報を締め、請求ヘッダー、集計明細、日報関連を保存する。
- 確定、承認、確定解除、除外、印刷済みの状態がある。
- 印刷APIはフラグ更新だけで、PDF本体は生成しない。

### 支払

- `payments`、`payment_details`、`payment_daily_reports`がある。
- 承認済み・未支払の日報を締め、支払ヘッダー、稼働明細、控除明細、日報関連を保存する。
- 確定、承認、確定解除、印刷済みの状態がある。
- 事務所費1,100円と保険料8,800円がコードとDB既定値へ固定されている。
- 印刷APIはフラグ更新だけで、PDF本体は生成しない。

### 前払

- `advance_payments`と`/api/advances`がある。
- 現行APIは`projects.payment_type = installment`の案件だけを対象にし、`installment_amount`を日数単価として使用する。
- 1か月を3期間に分け、日報の稼働日数または手入力日数から金額を算出する。
- この構造は「前払は案件単位」「分割返済はパートナー単位」という新要件と一致しない。

### 入出金、FB、Excel、帳票

- 月6回の管理回、入出金予定、入出金実績を分離するAPI・テーブルは確認できない。
- FBバッチ、出力履歴、対象予定との関連、取消・再出力を管理する実装は確認できない。
- Excel取込処理は確認できない。
- HTMLプロトタイプには収支・前払・分割等の表示案があるが、静的デモであり業務仕様または実装済み機能の根拠にはしない。

## 仕様との差分と実装上の注意

1. **前払と分割が混在している。** 現行の前払APIは分割案件設定を前払単価として流用している。既存列を名前だけ変えて延命しない。
2. **上書き額だけでは調整履歴にならない。** 調整額、理由、入力者、入力日時、請求・支払の別、元明細を独立して保持する。
3. **支払控除が固定値である。** 会費、G会費、任意保険、手数料等は、適用条件と有効期間を含むマスタまたは確定明細へ移す。
4. **計算根拠が明細化されていない。** 基本、時間超過、深夜、休日、距離、経費等を項目別の計算明細にする。
5. **確定解除と発行済み帳票の関係が未定義である。** 既発行PDFを変更せず、訂正・無効化・再発行を別版として残す。
6. **管理回と実行日が表現されていない。** 5日回から末日回までの業務上の所属と、予定日、個別上書き日、実行日を分離する。
7. **状態遷移の権限が不足している。** 日報承認、請求・支払確定、帳票発行、FB承認・出力、取消ごとに権限を定義する。
