# Issue #28 日報の深夜時間・深夜超過計算

> **状態**: N-01～N-07確定・実装Issueへの引継ぎ準備済み
> **対象Issue**: [#28 日報の深夜時間・深夜超過計算を確定する](https://github.com/afteib-links/Links-System/issues/28)
> **目的**: D-01から分離した深夜計算について、DB・API・計算処理へ固定する前に業務ルールを確定する。

## 1. 確定済みの前提

- 勤務時刻は勤務日を基準とする48時間表記で入力し、最大は`47:59`とする。
- 例として翌日4時は`28:00`と入力し、翌日の別日報へ自動分割しない。
- 休憩は開始・終了を個別登録せず、1日の合計休憩時間を`H:MM`形式で入力する。
- 拘束時間、実働時間、時間調整、通常超過、不足時間はD-01で定義済みである。
- 請求側と支払側では、単価、計算方式、対象可否、時間・金額の丸め条件を独立して設定できる構造とする。
- 新規案件の時間丸め初期値は15分、丸め方式は切り捨て、時間丸め段階は日ごとである。ただし案件条件で変更できる。
- 現行コードやプロトタイプにある`22:00～05:00`、0.25時間単位、ダミー単価は正式仕様ではない。

## 2. 用語

| 用語 | 意味 | 状態 |
|---|---|---|
| 深夜対象時間 | 契約で定めた深夜時間帯と、計算対象勤務時間が重なる時間 | 確定 |
| 通常超過時間 | 契約の基準時間を超えた時間 | D-01で計算単位を確定済み |
| 深夜超過時間 | 深夜対象時間と通常超過時間の両方に該当し、日報の深夜超過欄へ排他的に分類する時間 | 確定 |
| 深夜料金 | 深夜対象時間から深夜超過時間を除いた時間に適用する請求・支払明細 | 確定 |
| 深夜超過料金 | 深夜かつ超過に該当する時間へ適用する専用明細 | 確定。超過料金・深夜料金を重複加算しない |

## 3. 48時間表記での判定例

以下は、新規案件の初期深夜帯`22:00～29:00`を使用した確定済みの判定例である。

| 勤務入力 | 深夜対象候補 | 判定 |
|---|---|---|
| `20:00～28:00` | `22:00～28:00` | 翌5時を`29:00`として同じ勤務日に判定する |
| `23:00～31:00` | `23:00～29:00` | `29:00`以後は深夜対象外へ戻す |
| `20:00～47:00` | `22:00～29:00`、`46:00～47:00` | 深夜帯を24時間ごとに繰り返す |

## 4. 決定が必要な事項

### N-01 深夜時間帯

- **決定済み**: 全案件共通の固定時間帯にせず、案件条件で開始・終了を設定可能にする。
- **決定済み**: 請求側と支払側で異なる時間帯を設定できる。
- **決定済み**: 新規案件の初期値は勤務日基準の`22:00～29:00`（翌朝5時）とし、両側とも変更可能にする。
- **決定済み**: 基本業務が深夜で深夜料金を通常料金へ含む契約等では、深夜料金を別途計算しない設定を可能にする。
- **決定済み**: 請求側・支払側ごとに、深夜計算区分として「別途計算」「基本料金に含む」「対象外」を選択できる。
- **決定済み**: 「基本料金に含む」では深夜対象時間を社内の計算根拠として計算・保存するが、別料金を加算せず外部帳票へ深夜明細を表示しない。
- **決定済み**: 「対象外」では深夜時間自体を計算・保存・表示しない。
- **決定済み**: 請求側・支払側それぞれに複数の深夜時間帯を設定できる。
- **決定済み**: 新規案件は`22:00～29:00`の1区間だけを初期登録する。
- **決定済み**: 24時を超える終了時刻は勤務日基準の時刻へ展開し、24時間を超える勤務では設定した各深夜帯を24時間ごとに繰り返して判定する。
- **決定済み**: `20:00～47:00`に初期値を適用した場合は、`22:00～29:00`と`46:00～47:00`を深夜対象候補とする。
- **決定済み**: 深夜計算区分が「対象外」の側では、深夜帯の判定を行わない。

### N-02 休憩と時間調整

日報は合計休憩時間だけを保持するため、休憩が深夜帯に含まれるかを時刻から自動判定できない。

- **決定済み**: 日報へ「深夜帯内休憩時間」を追加する。
- **決定済み**: 1分単位で入力し、初期値は`0:00`とする。
- **決定済み**: 深夜帯内休憩時間は深夜対象時間からだけ控除する。
- **決定済み**: 合計休憩時間を超える入力は禁止する。
- **決定済み**: 深夜帯と勤務時間が重なり、合計休憩時間が正数なのに深夜帯内休憩時間が`0:00`の場合は警告するが、明示的な続行により保存・日次確認を許可する。
- **決定済み**: 深夜計算区分が「対象外」の側では使用しない。
- **決定済み**: 請求側と支払側の深夜時間帯が同じ場合は共通入力欄を1つ表示し、異なる場合は請求用・支払用へ自動分離する。
- **決定済み**: 両側の条件が再び同じになった場合は値を失わず共通入力へ自動的に戻す。
- **決定済み**: 自動分離・自動統合は、利用者、日時、切替前後の表示状態、判定根拠となった条件差を操作履歴へ保存し、一般的な操作履歴と同じ期間保持する。

- **決定済み**: 自動計算した深夜対象時間は直接上書きしない。
- **決定済み**: 「深夜時間調整」を別項目とし、正負の1分単位で入力する。調整理由は必須とする。
- **決定済み**: 調整後深夜時間は0分以上かつ当該側の計算対象勤務時間以下に制限する。
- **決定済み**: 請求側と支払側の深夜計算条件が同じ場合は共通入力、異なる場合は自動分離し、条件が同一へ戻れば値を維持して共通入力へ戻す。
- **決定済み**: 自動計算値、調整値、調整後時間、理由、入力者、日時と入力欄の自動分離・統合を操作履歴へ保存する。

### N-03 通常超過と深夜超過

- **決定済み**: 日報画面の「超過」「深夜」「深夜超過」を独立した排他的な計算明細とする。
- **決定済み**: 超過欄の最終時間には超過料金、深夜欄には深夜料金、深夜超過欄には深夜超過専用料金を適用する。
- **決定済み**: 各料金設定には請求額・支払額を別々に登録する。
- **決定済み**: 深夜超過時間へ超過料金と深夜料金を自動重複加算しない。必要な割増を含む単価を深夜超過専用料金として登録する。
- **決定済み**: 自動候補と理由付き調整を反映した最終時間を、各入力エリアの計算数量として保存する。
- **決定済み**: 時間は1分単位で、深夜帯かつ基準時間超過を「深夜超過」、基準時間超過のうち深夜超過を除いた時間を「超過」、深夜対象時間のうち深夜超過を除いた時間を「深夜」へ自動分類する。
- **決定済み**: 同じ1分を複数の入力欄へ重複計上しない。
- **決定済み**: 「深夜」と「深夜超過」はそれぞれ独立して「別途計算」「基本料金に含む」「対象外」を請求側・支払側ごとに設定できる。通常深夜を基本料金へ含め、深夜超過だけを別途計算する契約も扱う。

### N-04 計算方式と単価

- **決定済み**: 請求側・支払側それぞれに「別途計算」「基本料金に含む」「対象外」を設定できる。
- **決定済み**: 日報の料金単価エリアには、選択料金区分の「基本加算」「超過」「深夜」「深夜超過」の契約単価を請求・支払別に初期表示する。この表は通常の手動加算額や計算後合計ではなく、当該行へ適用する単価の表示・一時変更欄である。
- **決定済み**: 一時的に単価が変わる場合は、対象の日報作業行だけ請求単価・支払単価を直接変更できる。料金マスタ、他の日報、他の作業行へ反映しない。
- **決定済み**: 日報行で変更できるのは単価・固定額・割増率等の計算値だけとし、料金設定で定めた計算方式・計算式は変更しない。変更後の値を同じ計算式へ適用して対象行を再計算する。
- **決定済み**: 契約上の元の値、変更後の値、必須の変更理由、変更者、変更日時を保存して手動変更表示を付ける。
- **決定済み**: 日次確認済みの間は単価変更不可とし、確認チェックを外してから修正・再確認する。
- **決定済み**: 深夜料金と深夜超過料金も通常料金と同じ料金設定・計算方式の仕組みを使用する。
- **決定済み**: 深夜・深夜超過は請求側・支払側ごとに、対象可否、計算方式、単価・固定額・割増率、計算対象時間を独立設定でき、両側で異なる計算方式も許可する。
- **決定済み**: 自動計算した深夜時間は直接上書きせず、N-02で定めた理由必須の「深夜時間調整」だけを許可する。

### N-05 丸め

- **決定済み**: 深夜対象時間と深夜超過時間には案件の通常の時間・金額丸め条件を共通適用し、深夜・深夜超過専用の丸め条件は設けない。
- **決定済み**: 通常超過、深夜、深夜超過ごとに異なる丸め単位・方式・段階は設定しない。
- **決定済み**: 計算順序は「勤務時間と深夜時間帯の重複抽出→深夜帯内休憩の控除→理由付き深夜時間調整の反映→通常超過時間との重複判定→通常・超過・深夜・深夜超過への排他的分類→案件の時間丸め→料金計算後に設定段階で金額丸め」とする。
- **決定済み**: 時間帯の抽出・調整・分類は丸め前の1分単位時間で行い、その後に分類後の各時間へ案件条件の時間丸めを適用する。
- **決定済み**: 金額丸めの段階は通常料金と同じく、明細ごと・日ごと・月合計後から案件条件で選択する。
- **決定済み**: 請求側と支払側では、通常料金と同じ仕組みにより異なる丸め条件を許可する。

### N-06 他の料金区分との重複

- **決定済み**: 日報の各作業明細行では、通常、土曜、日祝、研修、スポット、任意料金等から料金区分を1つ選択する。
- **決定済み**: 選択した料金区分内に設定された「基本・超過・深夜・深夜超過」の単価・計算条件を使用する。
- **決定済み**: 土曜、日祝、案件独自休日、研修、スポット、任意料金と、別の料金区分に属する深夜料金を自動で重複加算しない。
- **決定済み**: 曜日・休日等から自動選択した料金区分は日報上で手動変更でき、変更後も最終選択した1区分内だけで計算する。
- **決定済み**: 別料金区分間の重複優先順位設定は設けず、最終選択した料金区分を計算根拠とする。

### N-07 保存・監査

日次確認版の計算結果へ最低限、次を保存する。

- 適用した契約条件・PriceSet・料金行のIDと表示名
- 請求側・支払側それぞれの深夜時間帯、対象可否、計算方式、単価・割増率
- 勤務時間と深夜帯の交差区間
- 休憩・時間調整の反映方法と反映前後の時間
- 通常超過時間との重複区間と、加算・置換・対象外の判定
- 丸め方法・単位・段階と、丸め前後の時間・金額
- 自動計算後の手動調整、理由、入力者、日時

- **決定済み**: 下書き中の自動計算結果は最新状態へ更新し、自動再計算の全世代は保存しない。
- **決定済み**: 単価等の一時変更、深夜帯内休憩、深夜時間調整、料金区分の手動変更等の手動操作は操作履歴へ保存する。
- **決定済み**: 日次確認時に上記の入力・計算根拠・結果を版付きスナップショットとして保存する。
- **決定済み**: 確認解除後に修正して再確認した場合は新版を作成し、過去の確認済み版を削除しない。
- **決定済み**: 案件×対象月の承認時には、対象月全体を承認時点の確定スナップショットとして保存する。

確定・再計算・帳票発行後の履歴は、D-01で定義したスナップショット・取消・新版発行のルールへ従う。

## 5. 計算例

以下の金額は実契約の単価ではなく、計算処理の受入試験だけに使用する匿名テスト値である。

### 5.1 日祝・深夜・深夜超過を含む請求／支払例

条件:

- 勤務は`20:00～30:00`、合計休憩と深夜帯内休憩はともに`0:00`、日次基準時間は8時間とする。
- 深夜帯は請求・支払とも`22:00～29:00`、時間丸めは15分単位の切り捨てとする。
- 勤務日は日祝で、最終料金区分は「日祝料金」とする。
- 請求側は、基本固定額20,000円、超過2,000円／時間、深夜2,500円／時間、深夜超過3,000円／時間とする。
- 支払側は、基本固定額15,000円、超過1,500円／時間、深夜は「基本料金に含む」、深夜超過2,000円／時間とする。

分類結果:

- 通常時間は`20:00～22:00`の2時間。
- 深夜時間は`22:00～28:00`の6時間。
- 深夜超過時間は`28:00～29:00`の1時間。
- 超過時間は`29:00～30:00`の1時間。
- 同じ1分を複数区分へ重複計上しない。

金額結果:

- 請求額は、基本20,000円＋超過2,000円＋深夜15,000円＋深夜超過3,000円＝40,000円。
- 支払額は、基本15,000円＋超過1,500円＋深夜加算0円＋深夜超過2,000円＝18,500円。
- 支払側の深夜6時間は社内根拠として保存するが、別料金を加算せず、外部帳票へ深夜明細を表示しない。
- 日祝料金区分内の4項目だけを使用し、通常料金区分の深夜料金を重複加算しない。

### 5.2 深夜帯内休憩と深夜時間調整の例

- 勤務を`20:00～28:00`、合計休憩を`1:00`、深夜帯内休憩を`0:30`とする。
- 深夜対象候補`22:00～28:00`の6時間から深夜帯内休憩30分を控除し、自動計算値を5時間30分とする。
- 理由付き深夜時間調整を`+0:15`とした場合、調整後は5時間45分とする。
- 15分単位の切り捨て後も5時間45分となる。
- 自動計算値、調整値、調整後時間、理由、入力者、日時を保存する。

### 5.3 48時間表記と深夜帯繰返しの例

- 勤務を`20:00～47:00`、深夜帯を`22:00～29:00`とする。
- 深夜対象候補は`22:00～29:00`と、24時間後の`46:00～47:00`とする。
- 翌日分の日報へ自動分割せず、勤務日の同一作業行として計算する。

## 6. 受入条件

- 深夜計算区分が「対象外」の側では、深夜時間を計算・保存・表示しない。
- 深夜帯と勤務が重なり、合計休憩が正数で深夜帯内休憩が`0:00`の場合は警告し、明示的な続行後は保存・日次確認できる。
- 深夜帯内休憩が合計休憩を超える場合は保存できない。
- 料金区分が日祝なら日祝区分内、研修なら研修区分内、スポットならスポット区分内の「基本・超過・深夜・深夜超過」だけを使用する。
- 自動選択された料金区分を手動変更した場合は、最終選択した区分だけで再計算し、選択元・変更者・日時を保存する。
- 日次確認後は計算関連項目を変更できず、確認解除後の修正・再確認では日次確認スナップショットの新版を作る。
- 案件×対象月の承認時には、承認対象月全体の確定スナップショットを保存する。

## 7. 完了条件

- N-01～N-07について、ユーザー合意または実装Issueへの明示的な移管先がある。
- `仕様MD/09_日報・精算・帳票_業務要件.md` と `仕様MD/05_decision_log.md` に確定内容を反映している。
- 請求側・支払側の計算例を最低1件ずつ記載している。
- 48時間表記、休憩、通常超過、休日・研修等との重複を含む受入条件を実装Issueへ引き継げる。
