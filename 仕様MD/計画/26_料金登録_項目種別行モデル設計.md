## 1. 目的・非目標

### 目的

- 金額データ詳細の入力を、現行の「計算種別 × 料金種別」マトリクスから、**料金カード＋項目種別の行一覧**へ切り替える。
- 項目種別はマスター登録し、日報・請求計算がコードを見て単価を解決できるようにする。
- 請求詳細名・支払詳細名を行ごとに持ち、帳票摘要の正とする。
- 現行の `price_sets` / `price_set_lines` と矛盾なく接続し、既存日報計算を壊さない（Phase A）。

### 非目標（今回の設計・初回実装に含めない）

- マトリクスへの列追加・セル交差入力の復活
- 祭日専用 `day_type` の新設（`休`は案件休日へマップ）
- 燃料Web取込の本番接続（Phase B）
- 月極を必須にする変更（第2段。初回は日極中心）
- アップロードされた実画面HTML・実単価のリポジトリ取り込み

## 2. 画面仕様

### 2.1 全体

金額データ（PriceSet）詳細画面の「料金項目」領域を本UIに置き換える。ヘッダ（名称・適用期間・案件紐付け・請求／支払の勤務・深夜・丸め設定）は現行を維持する。

### 2.2 カード（料金区分）

| 要素 | 内容 |
|------|------|
| 料金名称 | 必須。日報の料金区分名、帳票グループの基準 |
| 適用曜日 | チップ選択: 月・火・水・木・金・土・日・祝・休・ALL |
| 操作 | カード追加／コピー／削除。行の追加／削除／並び替え |

- **列の追加は禁止**（曜日や項目種別を横マトリクスに展開しない）。
- ALL 選択時は他曜日チップを解除し、`weekday_code=all` として保存する。
- 同一 PriceSet 内で、曜日（休・祝含む）の適用がカード間で重複したら警告する（保存は許可してよいが画面に明示）。

### 2.3 行（項目）

カード内の表。列順は次で固定する。

| 列 | 必須 | 説明 |
|----|------|------|
| 項目種別 | 必須 | `fee_item_type` マスターから選択 |
| 請求額 | 必須（0可） | 整数円。表示は `￥`＋桁区切り |
| 支払額 | 必須（0可） | 同上。請求と独立 |
| 請求詳細名 | 任意 | 請求帳票の摘要／表示項目名。`{企業名}` `{案件名}` `{料金名}` 等 |
| 支払詳細名 | 任意 | 支払帳票側。`{パートナー名}` 等 |

- 未入力の詳細名は保存時に既定生成: `{料金名称} {項目種別ラベル}`（請求）／同様に支払。
- 「料金項目名を行先頭に置く案」は採用しない（カードの料金名称と重複するため）。

### 2.4 項目種別が距離・テーブルのとき

行の下に折りたたみで付帯条件を出す（請求／支払それぞれ）。

- `distance`: 方式（日次超過／月累計超過）、基準km、（行の請求額・支払額＝超過単価）
- `table`: 計算型（超過×単価／全距離×単価／段階内累積／固定）、段階行（〜km・請求・支払）

保存先は §4.3。

### 2.5 操作上の禁止・注意

- 利益率列は必須にしない（任意表示可。保存しない方針は現行どおり）。
- 「自動計算で倍率展開してマトリクスを埋める」UIは本モデルでは行わない（必要なら別Issue）。
- 新規 PriceSet の既定カード例: 「平日料金」（月〜金）、「休日料金」（土日祝休）、必要なら空の「作業単価」（ALL）。距離は行追加で足す。

### 2.6 画面サンプル（架空・匿名）

```text
[平日料金]  [月][火][水][木][金] 土 日 祝 休 ALL
項目種別     請求額      支払額      請求詳細名           支払詳細名
基本日極     25000       22000       {企業名} 日極        {パートナー名} 日極
時間単価      2500        2200       {企業名} 時間        {パートナー名} 時間
時間外        2800        2400       {企業名} 時間外      {パートナー名} 時間外
深夜単価      3000        2600       {企業名} 深夜        {パートナー名} 深夜

[作業単価]   月火水木金土日祝休 [ALL]
項目種別     請求額      支払額      請求詳細名           支払詳細名
単価          3000        2000       キッティング         キッティング
単価          5000        4000       システム設定         システム設定
```

## 3. 項目種別マスター

### 3.1 格納

- `code_masters.category_code = 'fee_item_type'`（実装時に migration で初期投入）
- ラベル変更・並び順はマスター画面で可能とするが、**計算に使う code_value は削除せず無効化**する

### 3.2 初期コードと計算対応

| code_value | 表示名 | 数量の取り方 | 現行 `calc_type` + `price_type` への展開 | Phase |
|------------|--------|--------------|------------------------------------------|-------|
| `daily_basic` | 基本日極 | 日次1（出勤日） | `daily` + `basic` | A |
| `hourly` | 時間単価 | 時間。**不足控除の時間単価もこれ** | `hourly` + `basic`（不足スロットも同単価） | A |
| `overtime` | 時間外 | 超過時間 | `hourly` + `overtime` | A |
| `night` | 深夜単価 | 深夜時間 | `hourly` + `night` | A |
| `night_overtime` | 深夜時間外単価 | 深夜超過時間 | `hourly` + `night_overtime` | A |
| `unit` | 単価 | 日報の回数・件数 | 保存時は `hourly`+`spot` 等へ仮マップせず、`extra_data` に保持し lines は `calc_type_code=unit`（未知扱い）でも可 | B |
| `distance` | 距離単価 | 超過km等（付帯条件） | `distance` + `basic`、条件は `distance_rules` | A（条件UI）/ 計算は既存距離 |
| `table` | テーブル単価 | 段階表 | `distance` + tiered ルール | A（条件UI）/ 計算は既存段階 |

補足:

- **不足専用の項目種別は置かない**。不足控除は `hourly` 行の単価を使う。
- マスターに無い／未知の code は設定保存可、日報自動計算では使わない（現行の未知 calc と同じ）。
- 月極（`monthly_basic` 等）は第2段。設計上の予約のみ。

### 3.3 日報での解決

1. 勤務日の曜日・祝・案件休日から料金カードを自動候補（手動変更可）。
2. 選択カード内の行を `fee_item_type` で索引し、基本／超過／深夜／深夜超過／不足に割り当てる。
3. `unit` は作業明細の数量×単価（Phase B）。
4. 距離・テーブルはカード横断でも PriceSet の `distance_rules` を正とする（複数 `distance` 行がある場合は請求／支払それぞれ先頭有効行＋ルール）。

## 4. データモデル

### 4.1 `extra_data.fee_items` 新形

```json
{
  "schema": "fee_items_v2",
  "fee_items": [
    {
      "id": "fi_...",
      "name": "平日料金",
      "weekdays": {
        "mon": true, "tue": true, "wed": true, "thu": true, "fri": true,
        "sat": false, "sun": false, "holiday": false, "project_holiday": false, "all": false
      },
      "rows": [
        {
          "id": "fr_...",
          "item_type": "daily_basic",
          "billing": 25000,
          "payment": 22000,
          "billing_detail_name": "{企業名} 日極",
          "payment_detail_name": "{パートナー名} 日極",
          "sort_order": 10,
          "lineIds": {}
        }
      ]
    }
  ]
}
```

- 旧形（`calc_types` + `matrix`）が来た場合は §6 の読み替えで表示する。
- カード単位の `billing_summary_template` / `payment_summary_template` は廃止し、**行の詳細名**を正とする（カード共通テンプレが残っているデータは行未設定時のフォールバック）。

### 4.2 `price_set_lines` への展開（Phase A 互換）

選択された各曜日（`all` なら `weekday_code=all` の1系統）× 各行について1物理行を作る。

| 行の item_type | calc_type_code | price_type_code | billing/payment |
|----------------|----------------|-----------------|-----------------|
| daily_basic | daily | basic | 行の値 |
| hourly | hourly | basic | 行の値 |
| overtime | hourly | overtime | 行の値 |
| night | hourly | night | 行の値 |
| night_overtime | hourly | night_overtime | 行の値 |
| distance / table | distance | basic | 行の単価（表示・互換） |
| unit | unit（または保存のみコード） | basic | 行の値 |

- `hourly` 行がある場合、不足控除用に `price_type_code=shortage` の行を**同じ単価で自動生成**してよい（UIには不足行を出さない）。
- 展開後も既存 API の lines 配列形状を維持する。

### 4.3 距離・テーブル条件

- 正: `extra_data.distance_rules.billing` / `.payment`（現行 `04_calculation_logic.md`）
- `distance` / `table` 行の折りたたみUIは、このオブジェクトを編集する
- `table` 選択時は `mode=tiered`、`distance` は `daily_excess` または `monthly_excess`

### 4.4 曜日コード

| UI | 保存 |
|----|------|
| 月〜日 | `mon`…`sun` |
| 祝 | `holiday` |
| 休 | `project_holiday`（lines 展開時は休日判定側と組み合わせ。lines の weekday は `holiday` に畳むか、`other` を使う場合は実装Issueで固定） |
| ALL | `all` |

設計確定: **祭日専用コードは追加しない**。休＝案件休日。

## 6. 既存データの読み替え（表示・保存）

旧 `fee_items`（`calc_types` + `matrix[calc][price_type]`）→ v2 rows:

| 旧セル | 新 item_type |
|--------|----------------|
| daily × basic | daily_basic |
| hourly × basic | hourly |
| hourly × overtime | overtime |
| hourly × night | night |
| hourly × night_overtime | night_overtime |
| hourly × shortage | （行にせず、hourly が無ければ hourly 行を単価から生成） |
| distance × * | distance（ルールは distance_rules） |

- カード名は旧 `name`、曜日は旧 `weekdays`
- 請求／支払詳細名は旧摘要テンプレまたは既定生成
- 保存し直すと `schema: fee_items_v2` を付ける
- 読み替え不能な未知 calc は `item_type` に元コードを残し「計算未対応」表示

## 11. 合意済みの版管理・条件式仕様（Issue #106）

- 料金系列コードは企業単位採番の `FEE-{企業ID5桁}-{連番4桁}`、改定版は `-R001` 形式とする。
- 「料金改定」は同一系列に新しい版を追加し、旧版の終了日を新適用開始日の前日にする。前版・次版を閲覧できる。
- 最新版は通常編集可能。過去版の修正には理由を必須とし、監査ログへ変更前後を残す。
- 日報の確認済み・承認済み・請求済み・支払済みスナップショットは再計算しない。過去版修正時の再計算候補は未確認・未締め日報だけを列挙する。
- 基本案件から個別案件、別企業へのコピーは新しい料金系列コードを採番し、コピー元系列・版を系譜として保持する。通常はコピー後に独立する。
- 基本案件の改定を個別案件へ反映する場合は「旧基本版／新基本版／個別最新版」の3点比較を行う。片側だけの変更は自動統合し、同じ項目を両側が変更した競合は基本または個別を利用者が選択してから個別案件の新しい版を作る。
- 同じ項目種別の行は複数登録でき、上から最初に条件一致した行を採用する。空条件は常に一致する。
- 条件・請求式・支払式は許可変数、四則演算、比較、`IF/AND/OR/NOT/ABS/MIN/MAX/ROUND/ROUNDDOWN/ROUNDUP` のみ。JavaScript `eval`、任意関数、ネットワーク参照は禁止する。
- 未提供の将来変数を含む式は保存できるが、その行を下書き・計算対象外とする。式の閲覧・編集は管理者だけとし、一般利用者には「管理者設定済み」と表示する。
