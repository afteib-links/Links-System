## 1. 画面・入力

全画面を業務順に点検し、対象者・案件・期間・保存状態、情報量、文字サイズ、操作の欠けを改善する。検索条件・一覧位置・詳細展開を保持。PC中心、スマホも主要操作可能とする。

日報は時間入力を初期表示とし、日付・開始・終了・休憩・実働・状態を優先。距離・経費は全項目モードで表示し、隠れた値の件数と合計を示す。日付・見出し・主要操作を固定、入力16px。空欄と0、未入力・未保存・保存済み・確認済み・エラーを区別。保存で全体を再描画しない。

詳細は選択行直下に勤務日・対象者を示し、時間詳細、経費・追加項目、一時単価変更、コメント・計算根拠に区分する。同条件の請求・支払は共通入力。契約料金と計算根拠は折り畳む。

共通時間入力: NFKC正規化後、2.30 / ２．３０ / 2:30 / 230 → 02:30、1730 → 17:30、8 → 08:00。2.3は曖昧なのでエラー（2.03か2.30を案内）。分は00〜59、開始終了は47:59まで。符号付き時間調整も同じ解釈。クリックまたはAlt+↓で時分選択、1分単位と既存増減刻みを併用。不正入力は値を保持して欄内説明。

Tabは時間モードで開始→終了→休憩→次行、全項目モードで可視の編集可能入力欄順。ボタン・リンク・参照・ロック・非表示欄を飛ばす。詳細に入った場合は詳細内を巡回。Shift+Tab逆順、Ctrl+S保存、F2選択行詳細。通常金額は整数円、小数既存単価は勝手に丸めない。燃費・燃料単価は小数可。

## 2. PDF OCR

既存Excel/CSV取込を維持してPDFを追加。定型手書き日報を社内/NASだけで処理する。PaddleOCR PP-OCRv5を基準に依存・モデル版固定、別ワーカーで同時実行1。永続ジョブ、進捗、失敗、再試行、再起動復旧。QNAPと2GB ASUSTORで負荷測定。停止時も原本から手修正で取込可能。

用紙テンプレートは表・行・列範囲を保存し再利用。回転・傾き補正、ページ・行・欄の座標を保存。横並びの取込チェック / 実PDF行画像 / 原OCRと修正候補 / 現在日報と反映予定値。選択行の原本位置強調、拡大、全ページ、狭幅は縦並び。現在値との差、手修正、不確実性は色と文字で示す。右側の反映予定値の手修正を優先。適用操作まで日報を書き換えない。

実装構成（Issue #163）: PDF受付と比較・反映APIを既存取込の配下に追加し、永続キューを独立Pythonワーカーが同時1件で処理する。PP-OCRv5 mobile検出/認識モデルをCPU・1スレッド・小分けで利用する。モデルはビルド時に公式配布元からチェックサム照合して導入し、実行時のワーカーは外部通信のない内部ネットワークに置く。PaddleOCR 3.2.0 / PaddlePaddle 3.1.1を固定する。原本のPDF表示と手入力確認はOCR障害時にも利用できるようにする。

様式はページ単位の回転、表領域、行数、列境界を比率で登録する。読取りの曖昧さと信頼度は日付・時刻値と分離する。PDF反映APIは行ID・行の版・反映先ID・日報の期待版・反映欄・修正値・明示消去欄・理由を受け取り、空欄の自動消去を禁止する。PDF画像・OCR原読取値・監査は同じ保存期限と取込閲覧権限で管理する。

案件・パートナー・確認した勤務日・作業行で照合し、行順・推測日付で後続行をずらさない。疑問符は注意表示のみ。同日複数行の反映先は明示選択。新規・明確・警告なしだけ初期ON、既存・既取込・要確認はOFF。

行と欄単位で反映選択。手入力・前回後の修正値を保護。空OCRは消去しない、消去は明示。変更なし・再送は冪等スキップ。更新理由・前後・原読取値・版を記録、初回入力元不変。確認/承認/精算/年度締め保護中は通常取込不可。反映直前に版を照合。原本・派生画像は既存閲覧権限と3年保存方針、実帳票はGit禁止。

## 3. 締め期間・追加項目・燃料費

日報入力・承認・請求・支払・OCRを案件締め期間に統一。20日締め11月は10/21〜11/20。年月と期間開始/終了/適用締日を保存。確定過去データは変更せず、未確定は差分確認して移行する。

実装時の互換方式（Issue #162）: 既存日報または月次承認がある案件月は暦月の期間履歴として保存し、金額・帳票・承認スナップショットを更新しない。新規期間は案件締日（未設定時は企業、双方未設定は末日）で作成する。直前の保存済み期間と境界が異なる場合はその翌日から開始する移行期間と明示し、重複や空白を作らない。保存済み期間はマスター締日の変更で再計算しない。後続の保存済み期間と境界が矛盾する場合は登録を止め、期間の確認を求める。

未確定履歴の切替は案件単位の差分プレビューで行う。確認・承認・精算に使われた期間は保持し、対象期間・日報の版と金額を含むプレビュー署名を再照合して一括移行する。変更対象は対象年月と期間参照だけで、再計算は行わない。理由、操作者、前後の値を監査保存する。

日別/締め期間別の追加項目を複数保持。直接金額、単価×数量、燃料費。請求のみ/支払のみ/両方、金額独立。手動変更・負額は理由、確認/承認/帳票/収支へ接続、再反映で重複しない。

税込燃料費 = ceil(往復距離 / km毎L × 指定日価格) × 出勤日数。燃費はパートナー→全社、往復距離は案件→パートナー（業務距離とは別）、都道府県は案件→パートナー→全社。同案件同日1日、別案件は各1日、研修含む、欠勤/不要除外。途中の条件変更は適用条件ごとに日数を分けて合算。価格は期間内指定日（今日可）の単一単価。設定元/価格日/日額/勤務日/合計を固定。税込額に税を再加算しない。

価格履歴、日次取得時刻JST、取得結果を保存。欠測は過去価格候補/手動選択と理由必須。gogo.gs自動取得は利用許諾・取得方法確認後のみ有効化し、それまでは手入力で利用可能。

## 4. 年度締め

実装契約（Issue #165）: 通常集計の根拠は対象12締め月の月次承認スナップショット（日報・追加項目・月間距離）とし、未承認の場合は現時点実績と未確認理由を表示する。通常帳票の手入力調整は別明細として加える。11月尾部は日別実績・保存済み燃料の日別根拠を集計し、期間一括項目・月額・月間距離等は案件ごとに金額/理由/確認を入力する。新しい年度専用画面を事務作業と収支分析から開く。年度申請で根拠を固定して営業確認へ渡し、確定時に専用PDF2種を保存する。通常精算の確定処理は呼び出さない。年度保存対象の日別入力と、燃料の日別確定分の変更を拒否するが、後続12月部分の燃料追加や通常請求・支払作成は許可する。訂正は旧版を残した新版で行う。

12〜11月、表示「2026年11月期」。年額 = 12月締め〜翌11月締め通常総額 + 当年11月締日翌日〜末日 - 前年11月尾部除外額。前年尾部を含める設定可、初期除外。11月全額ではない。年単位金額分析だけに適用、利益率は調整金額から再計算。通常請求/支払/月別/入出金予定不変。

通常額・前年調整・当年追加・年額・未確認根拠を表示。事務作成→全案件営業確認（未設定なら管理者）→管理者/経営者確定。日別・燃料は実績自動、月額・月間距離等は計上額と理由を手動指定し確認。初年度前年調整は登録または該当なし確認必須。

専用請求/支払帳票・明細・PDF・設定を版付き固定、通常発行と区別。入出金予定/通常発行済状態/前払充当/控除繰越消化は作らない。訂正理由付き新版、通常締めとの照合差額を表示。
