# 日報起点の検証データ作成ツール

## 合意と安全境界

2026-09-10のユーザー合意計画に基づく。検証環境の管理者専用。元の業務DBの置換、本番操作、銀行送信は対象外。
設定、取込列割当、日報サンプル、ケースの採否を先に確認し、同じ設定版を後続生成へ渡す。
初期値は取込件数優先、ファイルなしは企業5・人物10・基本5・個別10・担当者3。直近3か月、基準日までの実績。

## 初回納品の境界

初回は取込・設定・サンプル・採否保存・匿名共有出力まで。サンプルは業務DBへ登録しない。
精算金額の概算を正式計算と表示しない。独立DB生成、業務計算アダプター、帳票、移送・復元は後続実装。
未実装の生成APIは501を返す。サンプル承認だけで生成完了とはしない。

## API / データ

`/api/test-data` は `LINKS_ENV=verification` かつ `TEST_DATA_TOOL_ENABLED=true`、DB_NAMEが `links_verification_tool_` 接頭辞のときだけ有効。NODE_ENV=productionも拒否。
認証・管理者権限を必須とし、本番では404。設定は新規管理テーブルへJSONで保存する。

- GET `/meta`: 初期設定・ケースカタログ・実装範囲
- POST `/imports`: csv/xlsx最大5ファイル、各2MB・合計10MB、xlsx展開後20MB。シート・行・列の上限検査。数式は禁止。
- POST `/normalize`: 列割当と維持/仮想化/未使用を適用。コードで関係を解決し、補完一覧とエラーを返す。
- GET/POST `/drafts`: 一覧/設定の新規保存
- GET/PUT `/drafts/:id`: 取得/楽観ロックによる版更新。更新は承認を失効させる。
- POST `/drafts/:id/preview`: 決定的な勤務サンプルを作成
- POST `/drafts/:id/approve`: 現在版・プレビューハッシュ・採否を照合して承認
- GET `/drafts/:id/share`: 匿名化設定・サンプル・説明をJSON出力。自由コメントと元データは既定で除外。
- POST `/drafts/:id/generate`: 未承認は409、承認済みも初回は501（業務生成未実装）

原本は初回ではメモリ内解析のみで永続保存しない。再利用用に維持を選択した正規化値は管理テーブルに保存される。
共有用には維持値を含めず仮想カタログを使う。輸出CSVの式注入を防ぐ。

## 検証

通常/早朝/翌日終了/残業/早退/研修/欠勤/不要/休日勤務のサンプルを検査。
非配送の距離0、未来実績禁止、勤務重複、参照整合性、設定再現性、必須ケース不足の明示を確認する。
承認API、楽観ロック、認証、環境遮断、共有時の機密値除去を自動テストする。

## 2026-09-11 列クリック連携（Issue #119）

- 左に取込先別の日本語項目、右にExcel列名・データ1行目・2行目を表示する。左→右、右→左の両順序で連携できる。
- Excel側のシート選択で切替える。各シートの取込先・対象ON/OFF・対応付けは切替後も保持する。
- 1項目に1列、1列に1項目。既存の別項目へ割り当て済みの列は確認後に移動し、旧連携を解除する。×で解除できる。
- 企業には担当・形態・検索用・企業番号・企業名・カナ・事業所名・郵便番号・住所・電話・FAX・契約担当者・業務内容を用意する。
- 担当・形態は元の文字列を保持する。コードマスターへ勝手に変換しない。検索用は取込設定の補助項目で、業務DB項目があるようには扱わない。
- 「全シートの対応付けを確認して設定に反映」で取込対象だけを正規化し、対象の種類だけカタログを更新する。未連携列は除外前に確認する。
- シート名・見出し・対応付けを設定JSONへ保存する。生の行データは対応付け設定に含めない。同じシート名・見出しでExcelを再選択した場合だけ対応付けを復元する。
- 未反映の対応付けがある間はサンプル保存・承認・共有を禁止する。既存設定との版管理を維持し、匿名共有には元列名・追加項目値を出さない。
- DBスキーマ・通常業務API・既存データは変更しない。業務データ生成・精算・帳票の未実装範囲は維持する。
