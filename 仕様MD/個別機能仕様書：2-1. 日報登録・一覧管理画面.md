# 開発指示：2-1. 日報登録・一覧管理画面（運用・承認フロー）の実装

事前に共有している「運送業務基幹システム」の全体方針およびデータベース設計に基づき、「日報登録・一覧管理画面」のフロントエンドプログラム（HTML/CSS/JavaScript）を作成してください。データの保存先はIndexedDB（またはLocalStorage）を用いたローカル保存を前提とします。

## 1. 画面の目的と前提
現場からFAX等で届く手書きの日報を、事務担当者が代理入力し、確定・承認を行うメイン運用画面。
将来的な拡張（スキャン画像のOCR取り込み、QRコード読み取り、WEB/メール自動登録）を見据え、データの「入力元区分」や「証跡画像（スキャンデータ）」を紐づけられる拡張性を持たせた設計とする。

## 2. 画面構成（SPAアーキテクチャ）

### 画面A：対象年月ベースの日報一覧画面
* **対象年月セレクタ**:
  * 画面上部に「前月 [ < ]」「YYYY年MM月（コンボボックスまたは直接入力）」「次月 [ > ]」のUIを配置し、表示する対象年月をシームレスに切り替えられるようにする。
  * 「データ取り込み」は年月セレクタと同じ行の右端へ配置する。
* **一覧エリア**:
  * 選択された年月に該当する日報・案件の一覧を表示（検索・ソート・フィルタリング可能）。
  * 各行には現在のステータス（未確定 / 日報確定 / 承認済 / 承認却下）を色分けしたバッジで表示する。
  * リストからクリックすることで、画面B（日報入力・承認画面）へ遷移する。
  * 対象案件、未入力、作業中、確認待ち、完了、要対応の集計カードをクリックすると、検索・締日・入力状況を維持したまま状態だけを絞り込む。作業中は入力中＋申請可能、要対応は差戻し＋訂正中を対象とする。

### 画面B：日報入力・承認画面（代理入力・ビューア連動想定）
* **スクロール**:
  * 画面タイトル、集計・操作部、表の列見出しを固定し、ホイール操作では日報行だけを縦スクロールする。
  * 詳細内の契約料金表には一覧用の検索・ソート行を表示しない。
* **将来拡張用UIレイアウト**:
  * 将来的に「左側にFAXのスキャン画像、右側に入力フォーム」を表示して見比べられるよう、画面を分割しやすいFlexbox/Gridレイアウトで構築しておくこと。
* **入力フォーム**:
  * パートナーNo（QRコードや手書き番号の入力想定）、案件No、車両、勤務日、開始/終了時間、休憩時間、経費（通行料等）。
  * 備考メモ欄（`memo`）: 承認者や入力担当者が連絡事項や修正指示（例：「金額が間違っています。正しくは25000です」等）を入力・閲覧できるテキストエリア。
  * LinksSys計算エンジンを呼び出し、自動計算された金額をプレビュー表示する（必要に応じて手動上書き可能）。
* **承認アクションボタンと制御**:
  * 現在のステータスに応じて「日報確定」「承認」「承認却下」「確定解除」などのボタンを表示・制御する。

## 3. 承認フローとデータ制御ルール（最重要）

日報データは以下のステータス（`status`）を持ち、厳密に状態遷移と編集権限を管理する。

1. **未確定 (Draft)**
   * 初期状態。すべての項目が編集可能。
   * アクション: 「日報確定」ボタンが押下可能。
2. **日報確定 (Confirmed)**
   * 事務担当者が入力を終えた状態。
   * 制御: **勤務時間や金額などの基本データはロック（編集不可）されるが、「備考メモ欄（`memo`）」のみ確定後も編集・追記を許可する。**
   * アクション: 「承認」「承認却下」ボタンが押下可能。
3. **承認済 (Approved)**
   * 管理者が内容を確認し、最終承認した状態。
   * 制御: **完全ロック（一切の変更不可）。**
   * 連携: このステータスになったデータのみが、フェーズ3の「本番の請求・支払処理」の取り込み対象となる。
4. **承認却下 (Rejected)**
   * 承認者が差し戻した状態。
   * 制御: ステータスは実質的に「未確定」相当に戻り編集可能となるが、画面上は「承認却下されたデータ」であることが明確にわかるよう警告色等でハイライト表示する。承認時に入力された備考メモ（却下理由など）が強調表示される。
5. **請求・支払画面でのプレビュー（仮表示）仕様**:
   * 「未確定」「日報確定」のデータであっても、請求・支払の一覧画面上には「仮の金額（プレビュー）」として表示・確認できる仕組みを担保すること（ただし本番確定処理は不可）。

## 4. データ構造・追加項目（日報トランザクション）

* `daily_report_id` (PK, 自動採番)
* `project_id`, `company_id`, `partner_id`, `vehicle_id` (各種FK)
* `target_year_month` (対象年月: YYYY-MM形式。一覧画面の切り替えキーとなる)
* `work_date` (勤務日), `start_time`, `end_time`, `break_time`
* `memo` (備考メモ欄: 確定後も編集可能なフィールド)
* **ステータス管理**:
  * `status` (状態: `draft`, `confirmed`, `approved`, `rejected`)
  * `rejection_reason` (承認却下時のコメント/メモ)
* **金額・計算結果（LinksSysエンジン出力の固定化）**:
  * `calculated_billing_amount`, `calculated_payment_amount` (自動計算額)
  * `override_billing_amount`, `override_payment_amount` (手動上書き額: NULL可)
* **将来拡張用項目（布石）**:
  * `input_source_type` (入力元区分: `manual` [デフォルト], `ocr`, `web`, `email`)
  * `scanned_image_url` (証跡となるFAX等のスキャン画像パス/URL)

## 5. プログラムソース作成の絶対条件
* すべての機能を省略せずに作成し、そのまま動作する完全なコードを出力してください。
* 年月切り替えUIやステータスバッジの表示変更、確定時のフォーム要素の `disabled` 制御（`memo` のみ除外）をJavaScriptで確実に実装すること。
* 仕様の不明点は勝手に補完せず、必ず質問してください。
