# 開発指示：1-2. パートナーマスタ管理画面の実装

事前に共有している「運送業務基幹システム」の全体方針およびデータベース定義に基づき、以下の仕様で「パートナーマスタ管理画面」のフロントエンドプログラム（HTML/CSS/JavaScript）を作成してください。データの保存先はIndexedDB（またはLocalStorage）を用いたローカル保存を前提とします。

## 1. 画面の目的
業務を担うパートナー（協力会社・個人事業主・専属ドライバー等）の基本情報、免許・安全管理情報、税務・各種区分情報、銀行口座、および持ち込み車両情報を統合管理する。
ここで設定された「パートナー区分」や「支払出力区分」は、後続の精算処理や帳票出力の自動判別に利用される。

## 2. 画面構成（SPAによる2画面切替型）
JavaScriptを用いてローディングなしで画面表示を切り替える構成とする。

### 画面1：パートナー一覧リスト画面
* **ヘッダー/操作エリア**: 氏名・名称での部分一致検索、パートナー区分（個人/企業/個人事業主）や契約区分（外注/給与）でのフィルタリング、ソート機能、「＋ 新規パートナー登録」ボタン。
* **データテーブル**: パートナーID、氏名/名称、パートナー区分、契約区分、連絡先、インボイス番号などを一覧表示。
* **各行のアクションボタン**:
  * 「編集」: 対象データを読み込み、画面2（詳細画面）へ遷移。
  * 「削除」: 確認ダイアログを表示し、了承時のみ論理削除（`is_deleted = true`）を実行。

### 画面2：パートナー詳細（編集・登録）画面
情報量が多いため、タブまたはセクションで視認性よく分割する。
* **基本情報セクション**: 氏名/名称、カナ、住所、連絡先、基本契約日、パートナー区分、契約区分、インボイス登録番号、前払い利用可否。
* **免許・安全管理セクション**: 個人免許有効期限、取得免許一覧、過去安全大会状況。
* **各種区分セクション**: 傷害区分、請負損害区分、貨物区分、Ｇ会区分、確定申告区分、ループ区分、支払出力区分。
* **銀行情報セクション**: 振込銀行口座情報。
* **車両情報セクション**: 「＋ 車両を追加」ボタンでパートナー所有車両を複数登録できる（1対多）UI。
* **アクションボタン**: 「保存（入力チェック込み）」「一覧へ戻る（キャンセル）」

## 3. データ構造（DB / IndexedDBカラム定義）

**システム共通項目（全テーブル共通）**
* `created_at` (作成日時), `updated_at` (更新日時), `is_deleted` (論理削除フラグ：デフォルトfalse), `extra_data` (将来の拡張用JSON領域)

**① パートナー基本情報テーブル**
* `partner_id` (パートナーNo: PK, 自動採番)
* `partner_name` (氏名・事業者名: 必須), `partner_name_kana` (氏名カナ)
* `zip_code`, `address` (郵便番号・住所), `contact_phone` (連絡先電話番号)
* `contract_date` (基本契約日)
* `partner_category_code` (パートナー区分: 個人 / 企業 / 個人事業主 - 区分マスタ参照)
* `employment_type_code` (契約区分: 外注 / 給与 - 区分マスタ参照)
* `invoice_number` (インボイス登録番号)
* `advance_payment_enabled` (前払い利用可否フラグ: boolean)
* **免許・安全管理**:
  * `license_expiry_date` (個人免許有効期限)
  * `license_types` (取得免許一覧: 複数選択テキスト/配列)
  * `safety_conference_history` (過去安全大会状況)
* **各種区分（区分マスタ参照）**:
  * `accident_insurance_code` (傷害区分)
  * `contractor_liability_code` (請負損害区分)
  * `cargo_insurance_code` (貨物区分)
  * `g_association_code` (Ｇ会区分)
  * `tax_return_code` (確定申告区分)
  * `loop_code` (ループ区分)
  * `payment_output_code` (支払出力区分: 請求書＋支払明細書 / 給与明細 などの帳票判別キー)
* **銀行情報**: `bank_name`, `branch_name`, `account_number`, `deposit_type`, `account_name`

**② パートナー所有車両情報テーブル（パートナーに対して1対多）**
* `vehicle_id` (車両KeyNo: PK), `partner_id` (FK)
* `vehicle_name` (車両名称), `vehicle_number` (車両番号)
* `inspection_expiry_date` (車検証有効期限)
* `insurance_expiry_date` (任意保険有効期限)

## 4. プログラムソースの作成に関する絶対条件
* 実装において、すべての機能を生かして作成してください。
* 処理時間がかかっても構いません。ソースコードが長くなることも全く問題ありません。
* 途中で「以下略」等の省略を一切せず、コピペしてそのまま完全に動作するコードを出力してください。
* 選択肢項目（パートナー区分、契約区分、各種分類など）に必要な汎用区分マスタは、プログラム内で初期データとして適切に補完・生成してください。
* コード作成にあたり、仕様の不明点があれば勝手に想像で補完せず、必ず質問して確認をとってください。
